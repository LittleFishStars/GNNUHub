## 踩坑记录（重要）

**GitHub 细粒度 PAT 权限陷阱**：推送代码**只**依赖 `Repository permissions → Contents: Read and write`。
- 改仓库描述走的是 Administration/Metadata 权限，创建 Issue 走 Issues 权限
- 这两项授权成功（HTTP 200 / 201）会**造成"权限已经好了"的误判**，但 `POST /git/refs` 仍返回 403
- 判据应直接用 `POST /repos/{owner}/{repo}/git/refs` 测试，而不是 PATCH 描述

**git 凭据助手干扰**：
- 本机全局配置 `credential.https://github.com.helper = !/usr/bin/gh auth git-credential`
- gh 内 token 已失效时会覆盖 URL 中内嵌的 token，导致读能过、写被拒
- 绕过方式：`git -c credential.helper= -c "credential.https://github.com.helper=" push ...`

**本机 SSH 连 GitHub 异常**：
- `~/.ssh/known_hosts:3` 的 github.com 主机密钥与当前实际不符（ECDSA），SSH 拒绝连接
- 当前返回的 ED25519 指纹 `SHA256:8s7dAW43...` 与 GitHub 官方 `SHA256:+DiY3wvv...` 不一致，未处理，改用 HTTPS 绕过
- `/etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf` 权限异常（Bad owner or permissions）

**其他环境信息**
- git 走本地 HTTP 代理 `127.0.0.1:41687`，curl 测试时可用 `no_proxy='*'` + 清空 proxy 变量绕过

### 关键技术发现

**验证码实测特征（重要）**
- 尺寸固定 **100 x 25**，PNG
- 固定 **4 字符**，字母数字混合，**大小写混用**
- **每个字符颜色随机且互不相同**，白底 → 必须先灰度化
- 无旋转/扭曲/干扰线，有效期 300 秒
- kaptchaType = "2"
- 结论：纯 Rust 模板匹配可行，但要先采集 300-500 样本训练字型库

**接口字段陷阱**
- 申请验证码时传入的 `id`（客户端随机）与响应返回的 `uid`（服务端）**不是同一个值**
- 提交登录必须用响应里的 `uid`，Python 版 `Captcha` 类误用了请求 id

**Python 版存在的问题（Rust 版已修正）**
- `login.py:77` 验证码错误时递归无上限 → 改为有界循环
- `api.py:52` `while True` 重试无上限 → 改为可配置次数
- `encode.py` 的 `Barrett` 类是假的，实际直接 `pow()` → 移除伪实现
- `Student.__init__` 中 SSO 跳转 `while True` 无上限 → 有界 + 目标域校验

**加密验证**：Rust 实现与 Python `encode_password` 输出逐字节一致，已写入单元测试固化基准值。
